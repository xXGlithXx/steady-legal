Accessibility

Last updated: 16 August 2026 — App version 1.0

This statement says what works, what doesn't, and what is being fixed. It is written from an actual audit of the app rather than from a template, so the gaps below are real ones and the list is not flattering.

What works today

VoiceOver

Every button that shows only an icon — the toolbar controls, the ••• menus, the send buttons, set completion toggles, the close and delete controls — has a spoken label describing what it does. Before August 2026 most of these announced only "Button", which made large parts of the app unusable with VoiceOver. Buttons whose state matters, such as a set's completion toggle, announce the current state rather than just the action.

Set rows are grouped, so entering one announces which set it is instead of reading a disconnected run of numbers — while leaving the weight and reps fields individually reachable and editable, which collapsing the row into a single spoken string would have taken away.

Keyboard

Every numeric keyboard in Steady — weight, reps, added minutes, the sign-in code — has a Done button above it. Those keyboards have no return key, so until August 2026 there was no way to put them away: tapping elsewhere did nothing and no key dismissed them.

Reduce Motion

Steady uses spring animations throughout. If you have Reduce Motion turned on in iOS Settings → Accessibility → Motion, the app follows it automatically — the springs become short fades and the press-scale effect is dropped. There is also a separate switch under Settings → Theme → Feel if you want the calmer motion without changing the system setting. The system setting alone is enough; the in-app switch only adds to it.

Text size

Steady follows the text size set in iOS Settings → Display & Brightness → Text Size and under Accessibility, including the larger accessibility sizes. Text grows up to 160% of its normal size and then stops.

The cap is deliberate. Steady's screens include set tables with columns and figures sized around their contents, and past about 160% those layouts start cutting text off rather than reflowing. Text that is smaller than you asked for is a compromise; text that is chopped in half is a bug. Where a number sits in a fixed column it shrinks to fit instead of truncating, so nothing is hidden behind an ellipsis.

Steady also has its own Larger Text setting under Settings → Accessibility, which adds to your phone's rather than replacing it — useful if you want Steady bigger without enlarging everything else.

Contrast

Every text colour was measured against every background in all six themes in August 2026. Fifty-four of the ninety combinations were below the 4.5:1 that WCAG AA asks for; the muted tiers were as low as 2:1. The palette was re-spaced so all text now clears 4.5:1 in every theme, with the hue of each theme kept intact. Turning on Increase Contrast, in iOS or in Steady, strengthens it further to at least 5.5:1.

Steady's own accessibility settings

Settings → Accessibility has Larger Text, Bold Text, Increase Contrast and Reduce Motion. These are additive: where iOS already has a setting on, Steady follows it, the row says so and is locked. Nothing in Steady can turn off an accessibility setting you have made at the system level.

Touch targets

Small icons are padded out to a touch-friendly tap area rather than being tappable only on the glyph itself.

Charts

The training-volume chart and the year activity grid each have a spoken summary — the recent average, the best week, the direction of travel, and how many days were logged — so the information in them is available without seeing them. The year grid in particular used to present 364 separate unlabelled squares to VoiceOver; it is now a single element that describes itself.

Colour and themes

Several themes are available under Settings → Theme, including light and dark options. Colour is not the only way any state is communicated — completed sets, for example, also change their icon.

No time limits, no flashing

Nothing in Steady expires while you are reading it, and there is no flashing or strobing content. Rest timers can be paused, extended or skipped.

What does not work yet

Text stops growing at 160%. If you use one of the largest accessibility text sizes, Steady will honour it up to that point and no further. This is the main remaining limitation, and fixing it properly means rebuilding the denser screens so they can reflow rather than just scale.

Also outstanding:

  • VoiceOver has been improved, not finished. Every icon-only control is labelled, set rows are grouped so you are told which set you are in without losing the ability to edit the fields inside, and the charts describe themselves. The reading order of the busiest screens has not been walked end to end by someone using VoiceOver as their only means of navigation.
  • Voice Control and Switch Control have not been tested.
  • No Reduce Transparency setting, deliberately. Steady's tab bar, cards and sheets are solid colour rather than frosted, so there was nothing for a switch to flatten — it was removed rather than left doing nothing. iOS's own setting is still honoured for the few blurred surfaces that do exist.
  • Verified on the sign-up, sign-in and onboarding screens only. The text scaling and contrast work was checked visually at an accessibility text size on those screens. The signed-in screens were fixed from the code and are covered by the shrink-to-fit behaviour, but have not had the same screen-by-screen visual check.

Standard applied

We are aiming at WCAG 2.2 Level AA as it applies to mobile applications, and at Apple's own accessibility guidance for iOS. Contrast now meets AA throughout, and text scaling meets it up to 160%. Because scaling stops there, and because the VoiceOver and Switch Control testing above is incomplete, this remains a statement of partial conformance with the gaps listed, not a claim of full compliance.

If something is in your way

Email avestaalam@gmail.com and describe what you were trying to do and what stopped you. Steady is built by one person, so replies usually take two to three days. Accessibility problems are treated as bugs, not as feature requests.

If you use an assistive technology that Steady works badly with, saying which one and which iOS version is genuinely useful — most of these problems are invisible without it.

How this statement is kept honest

It is reviewed whenever the interface changes materially, and at least once a year. If something listed as working stops working, it moves to the section above and the date changes.
